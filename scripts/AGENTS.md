# scripts/

## Purpose

Operator-facing helpers wired to npm scripts. They are dev and release tooling, not part of the
server's runtime — though `package.json` `files` does ship this folder.

## Ownership

- `setup-assets.mjs` (`npm run setup-assets`, bin `lpc-spritesheet-setup`) — acquires the external
  LPC asset pack.
- `make-showcase.mjs` (`npm run showcase`) — regenerates every rendered image the README embeds:
  `hero.png`, `gallery.png`, `walk-strip.png`, `sheet-katana.png`, `logo.png`,
  `social-preview.png`, plus the `showcase-credits.csv`/`.txt` sidecars.
- `make-architecture-svg.mjs` (`npm run diagrams`) — emits `docs/img/architecture.svg`, the one
  system picture that survives npm's markdown renderer. Needs no asset pack.
- `make-demo-gif.mjs` (`npm run demo`) — records a real stdio session against `src/index.js` and
  encodes `docs/img/demo.gif`, `demo-poster.png` and `demo-credits.csv`/`.txt`.
- `npm run assets` runs all three generators in that order.

## Local Contracts

- **Setup is idempotent by probe, not by lock.** It treats a directory as already installed when it
  contains both `sheet_definitions/` and `spritesheets/`, then exits without touching it. That probe
  is `hasAssets`/`assetCandidates` from `src/assets-dir.js` — the same functions the server uses, so
  the two can never disagree about what "installed" means. It requires `git` on PATH and fails
  loudly without it. The clone is unpinned (`--depth 1` at the pack's default branch) and no script
  records the revision fetched, so nothing here may claim a reproducible asset version.
- **Anything needing the pack imports `findAssetsDir()`** from `src/assets-dir.js` and exits with a
  "run `npm run setup-assets`" message when it returns null. Do not re-implement the search order in
  a script.
- **Every file in `docs/img/` is generated by exactly one of these scripts, and is committed.** The
  README embeds them, so they are stale the moment rendering changes and must be regenerated in that
  same pass. Never hand-edit or hand-place one. See `docs/AGENTS.md` for the image rules that bind
  the outputs.
- **Pixel art is baked at integer scale, and nothing embedded exceeds the README column.**
  `make-showcase.mjs` enforces both in code: `blit()`/`scale()` throw on a non-integer factor, and
  `writeImage()` throws above `MAX_EMBED_W` (1250px, the measured `.markdown-body` width). A
  fractional downscale is the bug these guards exist to prevent — crop to the blocks you want and
  upscale those instead of shrinking a whole sheet.
- **Committed renders carry attribution.** `showcase-credits.csv`/`.txt` and `demo-credits.csv`/`.txt`
  are generated beside the images they cover. An image added without its sidecar is a licensing
  regression.
- **`make-showcase.mjs` bypasses MCP** and drives `Catalog`/`SpriteEngine` directly. Its cast specs
  are preflighted against the live pack before any image is drawn, so a stale `itemId` or a color the
  chosen item does not offer fails once with the full list.
- **The showcase needs a bold TTF and says so.** Font registration tries a list of known paths and
  exits non-zero if none exists, because an unlabeled banner is a broken docs artifact — the old
  silent "skip the labels" fallback is gone. Keep the candidate list cross-platform; keep absolute
  paths out of anything that ships to users.
- **The demo is real bytes with authored timing.** `make-demo-gif.mjs` spawns the actual server and
  renders what it returned; only frame pacing is invented, and machine-specific absolute output paths
  are rewritten before display. `StdioClientTransport` strips `LPC_ASSETS_DIR` unless the script
  passes it in `env`. Files are validated (frame count, byte budget) before anything is written, so a
  failed run cannot destroy a committed asset.
- **Determinism is the contract for committed binaries.** No timestamps, no randomness, stable
  iteration order; re-running any generator must produce byte-identical output. Verify with two runs
  and `sha1sum`.

## Work Guidance

- Add a script by giving it an npm script name; an unreferenced `.mjs` here is invisible to operators.
- Print what was found: the asset dir used, the target chosen, every file written with its pixel
  dimensions and byte size, and the credit entry count. Silent success here is how contributors end
  up rendering against the wrong pack.
- Keep the three generators writing disjoint files. Two of them running at once is only safe because
  their outputs do not overlap.

## Verification

No test covers this folder. Correctness is proven by the downstream checks each script enables:
`npm test` after `setup-assets`, and `npm run assets` followed by two-run `sha1sum` comparison for
the images. `npm run diagrams` self-checks its own layout bounds and fails if they do not hold.
