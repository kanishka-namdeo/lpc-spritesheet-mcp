# docs/

## Purpose

Durable internals. This folder explains *why the port behaves as it does* and *what upstream can
do*. User-facing material stays in `README.md`; working rules stay in AGENTS.md files.

## Ownership

- `ARCHITECTURE.md` — the authoritative statement of engine behavior: the upstream-to-here map for
  the whole shipped runtime (`src/index.js`, `src/character.js`, `src/assets-dir.js` and the engine
  included), the "Local inventions" list of every intentional divergence, the tool-surface-to-engine
  table, and three fenced `mermaid` diagrams (module dependencies, one render call, disk layout).
- `capability-inventory.md` — a one-time survey of the **upstream** generator's parameter surface,
  animations, export formats, credits, and repo layout, written before the port existed. It carries
  its own "describes upstream, not this server" caveat at the top.
- `img/` — every image the README and the docs embed. All of it is generated; nothing here is art
  work. See the generated-image contract below.

## Local Contracts

- **`ARCHITECTURE.md` is a contract, not notes.** `src/engine/` edits are governed by it and
  `CONTRIBUTING.md` orders contributors to read it first. Any behavior change that alters a mapped
  file, a local invention, or an invariant updates this doc in the same pass; a divergence that
  turns out to be deliberate gets recorded here rather than left in a commit message.
- **Diagrams have two homes with two rules.** Detailed structure lives in `ARCHITECTURE.md` as
  fenced `mermaid`, because GitHub renders it natively: no binary, diffable, never stale. Keep them
  small (well under mermaid's `maxTextSize` 50000 / `maxEdges` 500), keep `accTitle:`/`accDescr:`,
  keep `%%{init: {"theme": "neutral"}}%%` so both GitHub themes stay legible, and avoid mermaid 12
  block types (`block-beta`, `architecture-beta`, `packet-beta`) — GitHub pins an older renderer.
  The single system picture in `README.md` is `img/architecture.svg` instead, because npm renders a
  mermaid fence as raw source text.
- **`img/` is generated — never hand-edit or hand-place a file in it.** Regenerate renders with
  `npm run showcase`, the SVG with `npm run diagrams`, the animated demo with `npm run demo` (or all
  three with `npm run assets`). They are deliberately committed (`*.png`/`*.gif` binary in
  `.gitattributes`, `*.svg` text) because the README embeds them, and they are stale the moment
  rendering changes.
- **Committed images are renders, so they carry attribution.** The upstream pack is OGA-BY/CC-BY-SA/
  CC-BY/GPL work, so every generated image has a credits sidecar beside it (`img/showcase-credits.*`,
  `img/demo-credits.*`). An image added to `img/` without one is a licensing regression, the same as
  a render without `-credits.csv`.
- **Pixel art must be baked, not browser-scaled.** GitHub's sanitizer strips inline `style`, so
  `image-rendering: pixelated` is unavailable in a README. Every image therefore ships at an integer
  multiple of its 64px source frames with `imageSmoothingEnabled = false`, and README `width=`
  attributes match natural pixel size. A fractional downscale (a smoothed sheet thumbnail) is a bug.
- **`capability-inventory.md` describes upstream, not this repo.** Treat it as background evidence
  for fidelity questions, never as a specification of what this server does. It is not generated by
  any script here, carries no upstream revision, and cannot be refreshed by a command — so its
  counts and line citations may predate the current pack. Verify against the live clone before
  relying on one, and fix the file when a measurement disproves it.
- **No machine-specific absolute paths in docs.** `docs/` is inside `package.json` `files` and ships
  to users. Refer to the pack as `$LPC_ASSETS_DIR` or the sibling `../lpc-generator-src`.
- **Duplicate facts get one owner.** Sheet geometry, the row/frame table, the tool table, and the
  credits duty currently appear in `README.md`, `CHANGELOG.md`, and both files here. Add a fact to
  exactly one place and link to it.

## Work Guidance

- Prefer a table with `upstream file -> local file` rows over prose when describing the port, and
  cite `path:line` upstream only where it is checkable in a clone.
- State divergence at the point of decision: what upstream does, what we do, why.
- When a doc claim and the code disagree, the code is the fact and the doc is the bug — fix the doc
  and say so in the report.

## Verification

`npm run diagrams` regenerates `img/architecture.svg` with no asset pack and fails loudly if its own
layout bounds do not hold; `npm run showcase` and `npm run demo` need the pack. Nothing checks the
prose: accuracy is maintained by the DOX pass, and CI checks rendering behavior only through `npm test`.
